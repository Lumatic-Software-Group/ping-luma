PingLuma — Privacy policy

Last updated: 1 May 2026. This page is static and is published with the Web App (e.g. via GitHub Pages).

1. Who this applies to

This policy describes the PingLuma Telegram bot, its Web App (this site’s dashboard), and the open-source software that powers them. If someone else runs their own copy of the bot, they are the data controller for that instance; this text describes the public project’s intended behaviour.

2. Telegram

When you interact with a bot, Telegram’s Privacy Policy applies to Telegram’s processing of your account, messages, and metadata. PingLuma does not replace Telegram’s terms.

3. What the bot receives

PingLuma uses the Telegram Bot API in the usual way: it can see updates your client sends to the bot, such as:

  • Commands and button presses (/start, /help, /list, keyboard actions).
  • The numeric Telegram user id and chat id needed to reply to you (as provided by Telegram to the bot).
  • Optional Web App data when you choose to send your measurement summary from the dashboard back to the bot (see below).

4. Web App / dashboard (your device)

The dashboard runs in your browser or in-app WebView. Network checks (such as HTTP requests, DNS lookups, and WebRTC ICE gathering toward messenger infrastructure) are initiated from your device to measure reachability from your network. Those probes go to third-party hosts operated by the messengers or their CDNs, under their policies — not to PingLuma’s dashboard files on GitHub Pages.

The dashboard does not implement its own user accounts and does not persist your scan results in the page storage beyond normal browser behaviour.

5. Sending results to the bot

If you tap the control that sends the outcome to Telegram, a small JSON payload is delivered to the bot, typically including:

  • A marker that identifies the payload type and a client timestamp.
  • An optional coarse country code detected on the client (if available).
  • For each supported messenger: identifiers you already know from the UI, plus boolean outcomes for chat-related reachability and, where applicable, call-related checks — and rough timings where measured.

This payload is used only to render the bot’s reply and optional aggregated reference signals (see below). It is not sold.

6. Crowdsourced reference (Iran-side signal)

To improve “works from Iran?” hints, the bot software may accept anonymous aggregate samples from users whose client reports an Iranian network path. Telegram user ids are never stored in plain form: they are hashed with a secret key that is generated in memory when the bot process starts. Samples live in memory only, expire automatically, and are not written to disk by this feature. Disable or tune this layer via your bot deployment configuration if you self-host.

7. Iran reference data (server)

The bot may combine public or configured sources (for example OONI summaries or optional HTTP references) to describe reachability from Iran. Those queries do not include your personal identity as part of the PingLuma design.

8. Hosting this page (GitHub Pages or similar)

Static files for the Web App (including this page) are often served via GitHub Pages or another HTTPS host. GitHub’s processing of IP addresses, logs, and repository metadata is described in GitHub’s privacy statement. This policy does not control GitHub.

9. Retention

Telegram retains chat history according to its own rules. Crowdsource aggregates in the bot process are ephemeral. Self-hosted operators should align logging and backups with their own policy.

10. Security

Transport uses HTTPS for the Web App. Telegram traffic uses Telegram’s channels. No security measure is perfect; use the official bot and the published Web App URL from a source you trust.

11. Children

The service is not directed at children under the age required by your jurisdiction to consent alone.

12. Changes

We may update this page; the “Last updated” date at the top will change. Material changes to practices should be reflected here.

13. Contact

For the open-source PingLuma project, questions may be opened as GitHub Issues on the repository that publishes this site. Replace this paragraph with your organisation’s contact details if you operate a private deployment.
